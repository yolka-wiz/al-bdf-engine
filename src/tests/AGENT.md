## 1. Layout overview
```
src/tests/
├── fixtures/   # byte-deterministic PDF corpus (committed)
├── fonts/      # bundled OFL-1.1 fonts for RTL tests (committed)
├── golden/     # 72 dpi PNG renders, one per fixture page (committed)
├── scripts/    # pdfgen.py + one generator per fixture (committed)
├── smoke.sh    # CLI smoke test (34 checks, wired as ctest target SmokeCli)
└── README.md   # original M2 harness notes
```
Everything here is committed and reproducible. Fixtures/goldens are
**byte-deterministic** — regenerating a fixture twice must yield identical
`sha256sum` (see [`README.md`](./README.md)).

## 2. Fixtures (`fixtures/`)
Byte-deterministic PDFs (no timestamps, fixed object order) used by unit,
integration, golden, and smoke tests.

| Fixture | Pages | Purpose |
|---|---|---|
| `test-baseline.pdf` | 2 | Pre-fork baseline ("Hello PDF4QT baseline!" + gray rect; "Second page with numbers 12345" + red rect). Goldens are the upstream reference. |
| `multipage.pdf` | 5 | Multi-page doc, distinct text + vector shape per page. |
| `image-doc.pdf` | 2 | Embedded image XObject (40x30 RGB, FlateDecode) + captions. |
| `overlap-text.pdf` | 1 | Three overlapping/rotated text lines. |
| `blank.pdf` | 1 | Blank page for add-text / search-text RTL tests. |

Add a new fixture by (a) writing a generator in `scripts/` (or extending
`pdfgen.py`) that produces byte-deterministic output, (b) committing the generated
PDF, and (c) registering it in the page-count/marker tables of `smoke.sh` and in
`UnitTestsGolden::golden_data()`.

## 3. Fonts (`fonts/`) — OFL only
Bundled for deterministic RTL (Persian/Arabic/Hebrew) integration tests. **All
three are SIL OFL-1.1** — permissive, redistribution allowed with license
preservation. No GPL/AGPL (ADR-0004):
- `Vazirmatn-Regular.ttf` — Persian (Arabic script), OFL-1.1.
- `NotoNaskhArabic-Regular.ttf` — Arabic, OFL-1.1.
- `NotoSansHebrew-Regular.ttf` — Hebrew, OFL-1.1.

**Add a font only if it is OFL** (or equally permissive) and document source +
license in `fonts/README.md`. Tests reference fonts via the
`TEST_FONT_PERSIAN`/`TEST_FONT_ARABIC`/`TEST_FONT_HEBREW` compile definitions
(see [`../UnitTests/AGENT.md`](../UnitTests/AGENT.md)).

## 4. Golden images (`golden/`)
72 dpi PNG renders, one per fixture page, named `<stem>_Image_<k>.png` (e.g.
`multipage_Image_1.png`). `UnitTestsGolden` renders every fixture with
`PdfTool render --page-first 1 --page-last N --image-format png --image-res-dpi 72`
and compares the **SHA-256 of each page** against these files.

- `test-baseline.pdf` goldens are the **pre-fork upstream reference** and must
  hash-match exactly — never regenerate to silence a failure.
- Other goldens are fork-anchored regression anchors.
- **To (deliberately) regenerate**: rebuild, then render each fixture at 72 dpi
  with the current `PdfTool`, replace the matching `*.png` files, and document
  the change in the commit message. `test-baseline.pdf` is not generated by
  `scripts/`; it is the preserved M0.5 fixture.

## 5. Test-source generators (`scripts/`)
- `pdfgen.py` — deterministic PDF writer used by the fixture generators.
- `make-multipage-pdf.py`, `make-image-pdf.py`, `make-overlap-pdf.py` — one
  generator per generated fixture. Run them to a temp path, verify byte-identity
  across two runs, then copy into `fixtures/`:
  ```sh
  python3 scripts/make-multipage-pdf.py /tmp/multipage.pdf
  python3 scripts/make-multipage-pdf.py /tmp/multipage2.pdf
  sha256sum /tmp/multipage.pdf /tmp/multipage2.pdf   # must match
  ```
  (`test-baseline.pdf` is the exception — not generated.)

## 6. `smoke.sh`
CLI smoke test exercising `info`, `fetch-text`, `render` (72 dpi PNG), and
`unite` invariants on the corpus, plus `recognize-text`/`delete-object` when
present in the binary. Invoked as the ctest target `SmokeCli` (see
[`../UnitTests/CMakeLists.txt`](../UnitTests/CMakeLists.txt)) and standalone:
```sh
QT_QPA_PLATFORM=offscreen src/tests/smoke.sh            # defaults: ./build/bin/PdfTool, ./fixtures
QT_QPA_PLATFORM=offscreen src/tests/smoke.sh <PdfTool> <fixtures-dir>
```
- Uses `expect_exit <code> <desc> <cmd...>` (assert exit code), `page_count`
  (parse `info` output), and `command_present` (detects whether a command exists
  by comparing `--help` headers).
- Fixture expectations are the `PAGES`/`TEXT` associative arrays; add/update rows
  when you change a fixture. A fixture is skipped (not failed) when its file is
  absent. Exit code 0 = all checks passed.

## 7. Rules & pitfalls
- **Never update goldens to silence a failure.** A mismatch means the renderer
  changed; investigate first. Only re-anchor deliberately and document it.
- **Never modify committed fixtures/goldens/smoke.sh for a code change** unless
  the change genuinely requires new regression anchors.
- **Only OFL/equally-permissive fonts** may be added.
- **Determinism is mandatory** — regenerated fixtures must hash identically or
  golden/smoke tests will fail.
- When adding a fixture/font, update the corresponding registries:
  `smoke.sh` (`PAGES`/`TEXT`), `UnitTestsGolden::golden_data()` (page counts), and
  the compile definitions in `UnitTests/CMakeLists.txt` if a test needs a new path.
- Note: `AGENTS.md` mentions `src/tests/golden/run.sh`, but it does **not**
  exist — regeneration is done via `scripts/` + `PdfTool render` + commit.
