# ADR-0006: Forms and digital signatures via CLI

- Status: accepted
- Date: 2026-08-04
- Deciders: user, Yolka
- Supersedes: none

## Context

The product goal is a headless PDF editing CLI. Forms (interactive AcroForm
fields) and digital signatures are the next milestone after the RTL
read/write/search core shipped in M0-M7. PDF4QT ships a full forms engine
(`PDFForm`, `PDFFormManager`, `PDFFormField`) and a signature verifier
(`PDFSignatureHandler`, `PDFSignatureFactory`) but only exposes both through
its GUI. We need CLI commands.

## Decision

Add three commands to `PdfTool`:

1. **`form-list`** — enumerate interactive form fields (name, type, value,
   page, rect, read-only). Read-only; walks the AcroForm tree via
   `PDFForm::parse`. Handles the common real-world case of a declared-but-empty
   AcroForm (`/Fields []`) gracefully.

2. **`form-fill`** — set field values and write a new document. Repeated
   `--field <name> --value <v>` pairs; the value object type is inferred from
   the field type (text string, button `On`/`Off` name, choice string). Uses
   `PDFFormField::setValue` with a `PDFDocumentModifier` + `PDFFormManager`
   wired to the *original* document (object numbers are stable in the
   builder's copy, so appearance lookups stay valid). Widget appearance
   streams are regenerated by the core.

3. **`sign`** — apply a PKCS#7 detached digital signature
   (`adbe.pkcs7.detached`, `Adobe.PPKLite`). Adapted from upstream's
   `SignaturePlugin` byte-range algorithm:
   - reserve the signature contents with a same-size probe signature (PKCS#7
     detached size depends only on key + cert chain, not data length),
   - write the document, locate the placeholder, compute `/ByteRange`,
   - patch the four ByteRange integers **in place** via fixed-width strings
     (the live-buffer `lastIndexOf` walk — each patch consumes one
     placeholder),
   - sign the two covered byte ranges with `PDFSignatureFactory::sign`
     (OpenSSL `PKCS7_sign`),
   - write the final signature hex back into the reserved gap.

   `verify-signatures` (upstream tool, already registered) validates the
   result; a one-byte content tamper makes it report `Signature: Error`.

`--rect-x/--rect-y/--rect-w/--rect-h` (renamed from `--x/--y/--w/--h` to avoid
clashing with the help parser's `-h`) place a visible signature widget;
omitting them produces an invisible signature.

## Consequences

- Forms and signatures are now scriptable headlessly — a first-class CLI
  feature, not GUI-only.
- The sign command depends on OpenSSL (already a hard dependency of the
  library via verification), so no new runtime dependencies.
- Signing with a PKCS#12 file means the private key password is passed on the
  command line — acceptable for a CLI tool, but documented; a future
  `--password-file` option would harden this.
- Test coverage: `UnitTestsFormSignature` builds a synthetic AcroForm, fills
  it, signs it, verifies the signature, and asserts tamper detection.
